==== 2026-10-03 — action-ref form and the lockfile, reconciled at the root (#34)

* *`+codeql.yml+` refs restored to the symbolic form* `+@v4.38.2+`, with the
resolved commit moved to `+actions.lock+` — `+github/codeql-action@v4.38.2+` →
`+sha1-2892aa5e…+`. Both halves change in one commit: a `+uses:+` ref the lock
does not vouch for is a `+startup_failure+`, not a stale lock.
* *The codeql-action `+ignore:+` hold is withdrawn.* The "v4.38.1/4.38.2 is
blocked estate-wide" belief (nexia-list#100) does not survive measurement:
every commit it called blocked is one where the workflow ref was changed and
`+actions.lock+` was not, and v4.38.2 runs green in the estate on a
consistent lock (`+hyperpolymath/panic-attack+`, 2026-10-01).
* *The estate's scanner pin is the other half of the reconciliation, and it
was the missing half.* Retiring the `+DependencyPinning+` acknowledgement only
works if the gate runs a lock-aware scanner. It did not: `+governance.yml+`
pinned `+hyperpolymath/standards@da2c748a+`, whose `+HYPATIA_PIN=0e913426+`
(2026-09-06) is 134 commits older than the lock-aware rule and still tests a
raw `+uses: owner/repo@vN+` regex that has never heard of `+actions.lock+` —
so `+actions/checkout@v7.0.1+` in any workflow was a finding no matter what
the lock recorded. Both Hypatia callers (`+governance.yml+`,
`+hypatia-scan.yml+`) now pin `+standards@71bb615e+` ("pin Hypatia baseline,
warn≡medium, self-fresh lock gate", #1121), whose `+hypatia-ref+` default is
`+51ab6496+` and therefore contains hypatia#762. The job set is identical
across the bump, so this moves the scanner pin and nothing else.
* *`+.hypatia-baseline.json+` sheds its `+DependencyPinning+` entry.* With a
lock-aware scanner the finding does not exist: `+check_unpinned_actions/2+`
accepts a symbolic ref that `+actions.lock+` records for that exact workflow,
and reports only a ref with no lock entry, an invalid lock, or a lock that
disagrees with the workflow. The entry's own note said to remove it once the
estate reconciled the scanner with the lockfile model — this is that moment,
and it is why the entry is deleted rather than renewed. The four `+SD022+`
entries are a different defect (SD022 does not skip repo-qualified
`+src/<dir>/+` references) and were never #34's subject; they are re-homed to
#78 with their expiry deliberately not extended.
* *The scanner's collateral was triaged, and four of the eight are gone.*
Moving the pin forward 134 commits turned on rules the old scanner never ran.
Four acknowledged findings were discharged outright, not renewed:
`+WH008+` on `+scorecard.yml+` (the line handed the whole secret scope to a
reusable that reads no secret at all — `+scorecard-reusable.yml @da2c748a+` has
no `+secrets.+` reference to satisfy); `+RE001+` on `+labels.yml+` and
`+label-triage.yml+` (`+secrets.GITHUB_TOKEN+` → `+github.token+`: the same
token, no secrets context, so the jobs no longer resemble a secret-bearing
egress path); and `+hardcoded_tmp+` in `+scripts/install-idris2.sh+`
(`+rm -rf /tmp/Idris2+` and a fixed-path clone replaced by `+mktemp -d+` plus
`+trap … EXIT+` — private dir, no predictable name, and a failed build no longer
leaves a half-clone for the next run to build on top of).
* *Four remain, and they are blocked on an upstream declaration, not on work
here.* The three surviving `+WH008+` findings call reusables that reference
secrets WITHOUT declaring them under `+on.workflow_call.secrets+`
(`+mirror-reusable.yml+` reads seven per-forge SSH keys and says so in its own
header; `+hypatia-scan-reusable.yml+` reads `+GITHUB_TOKEN+` and
`+HYPATIA_SCAN_PAT+`; `+secret-scanner-reusable.yml+` reads `+GITHUB_TOKEN+`).
GitHub documents that referencing an undeclared secret works only for
`+inherit+`, so a caller's choice today is "hand over every secret in scope" or
"break the call"; the fix belongs to `+hyperpolymath/standards+` and is filed
there as #1141. The fourth, `+RE001+` on `+push-email-notify.yml+`, is a dormant
estate template (`+if: vars.PUSH_EMAIL_ENABLED == 'true'+`) whose suggested
control — `+step-security/harden-runner+` — is used by zero estate reusables.
Each surviving entry now names its discharge condition and points at #82; the
`+expires_at+` is unchanged.
* *DEBT I-10 and ADR-010 re-scoped, not rewritten.* The Dependabot-actor
attribution is downgraded to unproven; the measured variable is the ref form
across two epochs. The decision — `+gh actions-lock+` is the bump mechanism,
Dependabot is a notifier — stands and is unchanged.
