=== [0.2.0] - 2026-10-07

The first release whose tagged commit passed CI. `+v0.2.0+` is tagged on the
squash merge of this release PR, after the push-to-`+main+` run of
`+Build, test and benchmark+` on that same commit came back green. All six
`+.ipkg+` packages now declare `+version = 0.2.0+`.

`+v0.1.0+` was tagged retroactively on 2026-10-07 at `+a4e589a+` (PR #12, the
last commit of 2026-06-24). No CI ran at that commit, and this changelog had
no `+[0.1.0]+` section when it was made; see that section below.

The entries below, collected under `+[Unreleased]+` from 2026-06-25 to
2026-10-07, make up 0.2.0.

==== 2026-10-07 — first proofs about another repository's code

* *proven's vector-clock merge proved a join-semilattice, against proven
itself.* `+integrations/proven/src/ProvenSubject/OrderingLaws.idr+` imports
`+Proven.SafeOrdering+` from proven at `+integrations/proven/PROVEN_PIN+`
(`+53600326+`) and proves eight laws of its `+mergeVT+`/`+zeroVT+`/`+tickVT+`:
commutativity, associativity, idempotence, two-sided `+zeroVT+` identity, both
upper bounds, and `+tickVT+` advancing its own entry by one. They are tested
in the new `+proven-ordering-laws+` executable (8 Actually-Proven, three reject
controls). They are not counted in the spec suite's 29.
* `+scripts/prove-proven-ordering.sh+` builds them against a throwaway package
prefix, so the toolchain prefix stays clean. CI fetches the pinned commit and
runs it as a hard gate. A `+mergeVT+` mutated to `+(+)+` fails it with five
compile errors. `+scripts/ci-build.sh+` runs it locally when the proven
checkout holds the pin.
* `+scripts/ci-build.sh+` now looks for proven at
`+$HOME/developer/hyper-repos/CORE/proven+`, where the clone now lives, and no
longer at the dead `+/home/user/proven+`.

==== 2026-10-06 — the min-plus semiring completed; max-plus for bench bounds

* *Min-plus is now a full commutative semiring, every axiom proved.*
`+src/ProvenTests/Tropical.idr+` adds `+otimesAssoc+`, `+otimesIdentityL+`,
`+otimesDistribL+`/`+otimesDistribR+` (via `+plusMinNDistribL/R+`) and
`+otimesAbsorbL+`/`+otimesAbsorbR+`, all total under `+%default total+`.
Before this the module was called a semiring while proving neither
distributivity nor `+PosInf+` annihilation.
* *Max-plus over `+Nat+` for worst-case bench bounds* (sequential composition
= `+`, branch = `+max+`), in the same module: `+max+`
comm/assoc/idem/identity 0, `+`+` comm/assoc/identity 0, and distributivity
of `+`+` over `+max+` on both sides. It is *not* a semiring — the
`+max+`-identity 0 does not annihilate `+`+` — and the module header says so.
It lives in `+Tropical.idr+` rather than a new module because a 33rd library
module needs `+STATE.a2ml+` `+library-modules+` updated, which this change
does not touch.
* *17 new Actually-Proven tests* in
`+tests/ProvenLawsTests/TropicalLawsTests.idr+` (spec suite 75 → 92, 12 → 29
Actually-Proven). Each rung is built with `+rung+` at the full law
statement, so the citation is the checked term. Two `+failing "Mismatch between"+` reject controls
assert false laws (max-plus 0 annihilating `+`+`, min-plus `+⊗+`
idempotence) do not typecheck.
* *Wrong comment fixed* in `+src/ProvenTests/TypeSafe/Tropical.idr+`: `+min(x,
0) = x+` is false; `+min+`'s identity is `+inf+`. The matching assertion
message in `+tests/TypeSafeTests/TropicalTests.idr+` is corrected too.

==== 2026-10-06 — rung citations are derived from the term (#87 review)

* *`+rung+` macro* (`+src/ProvenTests/Types.idr+`): one quoted theorem name
supplies both the proof term and the printed citation, elaborated against the
full statement at compile time. Every ladder (Laws suite, Baton, Cells) is
built with it, and no rung uses `+_+` as its statement any more.
* *Correction to the entry below:* `+Witness+` alone did not stop a rung
whose `+theorem+` string named a missing theorem; only its *term* had to
exist. That is now true for every rung built with `+rung+`; a hand-built
`+Witness+` with a free label still compiles and is kept as a residual control.
* *SpecSuite controls* now pin the macro's own reflection errors, and a
compile-time `+Refl+` checks that the derived citation is the literal name.
* *`+covering+` is allowlisted:* `+scripts/check-escape-hatches.sh+` fails on
any function-level `+covering+` that is not one of seven exact I/O
file:function pairs, closing the route by which a `+covering+` citer could
cite a non-terminating theorem. Three planted controls give rc=1.
* *Dead `+emptyProofLadder+` / `+addProofStep+` removed*
(`+src/ProvenTests/Classification.idr+`): `+List ProofStep+` helpers that
nothing called.

==== 2026-10-06 — the Actually-Proven tier carries its proofs

* *`+proof_ladder+` is now `+List1 Witnessed+`* (`+src/ProvenTests/Types.idr+`):
each rung holds an erased proof term at an explicit statement, so an
Actually-Proven claim citing a missing theorem, or a real theorem for the
wrong property, no longer compiles. Every existing ladder (Laws suite, Baton,
Cells) was converted; all 12 polymorphic law statements typecheck.
* *Three rejection controls* in `+tests/SpecSuite/Main.idr+` (`+failing+`
blocks, exact errors measured first) plus one recorded positive control: the
trivial witness `+Witness s () ()+` still compiles, and the docs say so.
* *The dead `+ActuallyProvenEvidence+` record is removed*
(`+src/ProvenTests/Classification.idr+`): strings-only, with a possibly-empty
ladder, and used by nothing.
* *`+integrations/proven+` no longer constructs in-build Actually-Proven
evidence from another repo's ledger.* `+Graded+` separates the tier `+claimed+`
from proven's ledgers from the provenance `+heldHere+` (at most
Provisionally-Proven); report counts are unchanged and the sanity gate fails if
any external module ever holds Actually-Proven.
* *`+EchoTypes/README.adoc+` corrected:* `+echo-types+` holds 219 `+.agda+` files
(217 `+--safe+`); the 07-28 "no formal artefacts" claim counted only
`+.idr+`/`+.lean+`/`+.v+`.

==== 2026-10-03 — action-ref form and the lockfile, reconciled at the root (#34)

* *`+codeql.yml+` refs restored to the symbolic form* `+@v4.38.2+`, with the
resolved commit moved to `+actions.lock+` — `+github/codeql-action@v4.38.2+` →
`+sha1-2892aa5e…+`. Both halves change in one commit: a `+uses:+` ref the lock
does not vouch for is a `+startup_failure+`, not a stale lock.
* *The codeql-action `+ignore:+` hold is withdrawn.* The "v4.38.1/4.38.2 is
blocked estate-wide" belief (nexia-list#100) does not survive measurement:
every commit it called blocked is one where the workflow ref was changed and
`+actions.lock+` was not, and v4.38.2 runs green in the estate on a
consistent lock (`+hyperpolymath/panic-attack+`, 2026-10-01).
* *The estate's scanner pin is the other half of the reconciliation, and it
was the missing half.* Retiring the `+DependencyPinning+` acknowledgement only
works if the gate runs a lock-aware scanner. It did not: `+governance.yml+`
pinned `+hyperpolymath/standards@da2c748a+`, whose `+HYPATIA_PIN=0e913426+`
(2026-09-06) is 134 commits older than the lock-aware rule and still tests a
raw `+uses: owner/repo@vN+` regex that has never heard of `+actions.lock+` —
so `+actions/checkout@v7.0.1+` in any workflow was a finding no matter what
the lock recorded. Both Hypatia callers (`+governance.yml+`,
`+hypatia-scan.yml+`) now pin `+standards@71bb615e+` ("pin Hypatia baseline,
warn≡medium, self-fresh lock gate", #1121), whose `+hypatia-ref+` default is
`+51ab6496+` and therefore contains hypatia#762. The job set is identical
across the bump, so this moves the scanner pin and nothing else.
* *`+.hypatia-baseline.json+` sheds its `+DependencyPinning+` entry.* With a
lock-aware scanner the finding does not exist: `+check_unpinned_actions/2+`
accepts a symbolic ref that `+actions.lock+` records for that exact workflow,
and reports only a ref with no lock entry, an invalid lock, or a lock that
disagrees with the workflow. The entry's own note said to remove it once the
estate reconciled the scanner with the lockfile model — this is that moment,
and it is why the entry is deleted rather than renewed. The four `+SD022+`
entries are a different defect (SD022 does not skip repo-qualified
`+src/<dir>/+` references) and were never #34's subject; they are re-homed to
#78 with their expiry deliberately not extended.
* *The scanner's collateral was triaged, and four of the eight are gone.*
Moving the pin forward 134 commits turned on rules the old scanner never ran.
Four acknowledged findings were discharged outright, not renewed:
`+WH008+` on `+scorecard.yml+` (the line handed the whole secret scope to a
reusable that reads no secret at all — `+scorecard-reusable.yml @da2c748a+` has
no `+secrets.+` reference to satisfy); `+RE001+` on `+labels.yml+` and
`+label-triage.yml+` (`+secrets.GITHUB_TOKEN+` → `+github.token+`: the same
token, no secrets context, so the jobs no longer resemble a secret-bearing
egress path); and `+hardcoded_tmp+` in `+scripts/install-idris2.sh+`
(`+rm -rf /tmp/Idris2+` and a fixed-path clone replaced by `+mktemp -d+` plus
`+trap … EXIT+` — private dir, no predictable name, and a failed build no longer
leaves a half-clone for the next run to build on top of).
* *Four remain, and they are blocked on an upstream declaration, not on work
here.* The three surviving `+WH008+` findings call reusables that reference
secrets WITHOUT declaring them under `+on.workflow_call.secrets+`
(`+mirror-reusable.yml+` reads seven per-forge SSH keys and says so in its own
header; `+hypatia-scan-reusable.yml+` reads `+GITHUB_TOKEN+` and
`+HYPATIA_SCAN_PAT+`; `+secret-scanner-reusable.yml+` reads `+GITHUB_TOKEN+`).
GitHub documents that referencing an undeclared secret works only for
`+inherit+`, so a caller's choice today is "hand over every secret in scope" or
"break the call"; the fix belongs to `+hyperpolymath/standards+` and is filed
there as #1141. The fourth, `+RE001+` on `+push-email-notify.yml+`, is a dormant
estate template (`+if: vars.PUSH_EMAIL_ENABLED == 'true'+`) whose suggested
control — `+step-security/harden-runner+` — is used by zero estate reusables.
Each surviving entry now names its discharge condition and points at #82; the
`+expires_at+` is unchanged.
* *DEBT I-10 and ADR-010 re-scoped, not rewritten.* The Dependabot-actor
attribution is downgraded to unproven; the measured variable is the ref form
across two epochs. The decision — `+gh actions-lock+` is the bump mechanism,
Dependabot is a notifier — stands and is unchanged.
