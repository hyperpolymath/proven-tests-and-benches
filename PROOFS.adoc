Required by the Proven Tests specification
(`standards/.github/ISSUES/cicd-optimization/004-tests-benches-standards.md` §3.1).

[IMPORTANT]
====
**29 spec-suite properties are now Actually-Proven** — the 12 laws in
`Proven/Laws.idr` (2026-07-28) plus 17 tropical and max-plus laws in
`Tropical.idr` (2026-10-06). The tier was empty until 2026-07-28.

The framework defines three tiers and implements all three. Measured on
2026-07-28, after the first Actually-Proven suite landed (before the 17
tropical and max-plus laws; the table is that snapshot):

[cols="2,1,4"]
!===
! Tier ! Uses ! Meaning

! `ActuallyProven`
! **12**
! Carries a proof term. The property holds for all inputs, checked by the typechecker under `%default total`.

! `ProvisionallyProven`
! **115**
! Checked at run time on named witnesses. Holds for those inputs.

! `Unproven`
! 0
! Declared but not checked.
!===

The other 115 tests are a `Bool` evaluated on concrete example data. That is a
real check — the suites exit non-zero when a property fails, verified by
injection — but it is **not** a proof, and this document does not describe it as
one. The `[Provisionally-Proven]` label on those lines is accurate and stays.
====

== The two tiers fail differently, and that is the point

[cols="2,3,2"]
|===
| Tier | Detects a false claim | When

| Provisionally-Proven
| Only if a chosen witness happens to expose it
| Run time

| Actually-Proven
| Always, for every input
| **Compile time**
|===

Demonstrated rather than asserted. Changing `mapIdentityProof` to claim
`map id xs = []` — a false statement — makes the build fail:

[source,console]
----
$ idris2 --typecheck proven-tests.ipkg
Error: While processing right hand side of mapIdentityProof.
       Mismatch between: [] and [x].
exit 1
----

No test runs. A provisional test with badly-chosen witnesses could pass on a
false property indefinitely; these twelve cannot exist while false.

`%default total` is load-bearing in `Proven/Laws.idr`: without it a proof could
be inhabited by a non-terminating term and Idris2 would accept it, which would
make every claim in the module worthless.

=== A limit worth stating plainly

Until 2026-10-06 the ladder was `List1 ProofStep`: **metadata** only
(description, file, line, theorem name). A ladder naming a theorem that did not
exist yielded a test labelled `[Actually-Proven]` on the strength of a string.

The ladder is now `List1 Witnessed` (`src/ProvenTests/Types.idr`). Each rung
carries the citation *and* an erased proof term at an explicit statement, and
every ladder builds its rungs with the `rung` macro (`src/ProvenTests/Types.idr`),
which takes one quoted theorem name, checks it against the full statement and
derives the printed citation from that same name. The typechecker rejects, at
build time:

* a rung citing a theorem that does not exist (renamed or deleted);
* a rung citing a real theorem for a property it does not prove;
* the old strings-only ladder shape.

All three are recorded as `failing` blocks in `tests/SpecSuite/Main.idr`, each
checked for its exact error before being placed there. The erasure means the
proofs cost nothing at run time.

**What it still cannot reject:** a statement that is true but is not the law the
test description names (`Witness s () ()` compiles), and a rung built with the
`Witness` constructor directly instead of `rung`, whose label is then a free
string beside the term. Both are kept in the spec suite as recorded positive
controls so nobody reads the tier as unforgeable.
That residual is now a visible lie in code, reviewable in a diff, where the old
one was an invisible string. The review rule: the statement passed with a rung
is the law's full statement, written out.

External subjects cannot hold this tier. `integrations/proven` grades proven's
modules from proven's own ledgers; their proofs are not re-checked in this
build, so it reports an Actually-Proven *claim* while the provenance it holds is
at most Provisionally-Proven, and its sanity gate fails if that ever changes.

== Why the distinction is kept sharp

A repository called `proven-tests-and-benches` that quietly used "proven" to
mean "the test passed" would be the most expensive kind of wrong: it would look
like the strongest evidence in the estate while being the same strength as any
other test suite. The three-tier `ProvenStatus` exists so the difference is
visible in the type system and in the output, not just in a README.

Promoting a property from provisional to actual is therefore a real piece of
work, not a relabelling. It means replacing

[source,idris]
----
prop : Widget -> Bool
prop w = someCheck w
----

with a statement quantified over all inputs and a term inhabiting it

[source,idris]
----
propHolds : (w : Widget) -> SomeCheck w = True
----

and passing `Witness step <statement> propHolds` rungs to `provenTest` rather
than `provisionalTest`.

==== Actually-Proven laws (12 theorems)

`src/ProvenTests/Proven/Laws.idr`, exercised by `tests/ProvenLawsTests/`. Each
is quantified over all inputs with a term inhabiting it.

[cols="3,3"]
!===
! Theorem ! Proof

! `id . f = f`, `f . id = f`, `id . id = id`
! Definitional (`Refl`)

! Induction; cons case rewrites by the IH

! `map g . map f = map (g . f)`
! Induction

! Induction — the left unit is definitional, this is not

! `length (xs ++ ys) = length xs + length ys`

==== Actually-Proven tropical and max-plus laws (17 theorems)

`src/ProvenTests/Tropical.idr`, exercised by
`tests/ProvenLawsTests/TropicalLawsTests.idr`. Each rung is built with
`rung` at the law's full statement, so a deleted or weakened theorem stops the
suite compiling, and the printed citation is the checked term.

[cols="3,3"]
!===
! Law ! Theorem(s)

! Min-plus `⊗` associative; `Fin 0` left identity
! `otimesAssoc`, `otimesIdentityL`

! Min-plus `⊗` distributes over `⊕` (left, right)
! `otimesDistribL`, `otimesDistribR` (via `plusMinNDistribL/R`)

! `PosInf` annihilates `⊗` (left, right)
! `otimesAbsorbL`, `otimesAbsorbR`

! Max-plus `max`: commutative, associative, idempotent, identity 0 (both sides)
! `mpOplusComm`, `mpOplusAssoc`, `mpOplusIdem`, `mpOplusIdentityL/R`

! Max-plus `+`: commutative, associative, identity 0 (both sides)
! `mpOtimesComm`, `mpOtimesAssoc`, `mpOtimesIdentityL/R`

! Max-plus `+` distributes over `max` (left, right)
! `mpDistribL`, `mpDistribR` (via `plusMaxNDistribL/R`)
!===

With the laws proved before 2026-10-06 (`⊕` comm/assoc/idem/identity, `⊗`
comm/right identity), min-plus over `Nat ∪ {PosInf}` now satisfies every
commutative-semiring axiom. Max-plus over `Nat` does *not*: its `⊕`-identity 0
does not annihilate `+` (`0 + a = a`), so it is a semiring minus annihilation.
Two `failing "Mismatch between"` blocks in the same test file require the type
checker to reject false laws — max-plus `0` annihilating `+`, and min-plus `⊗`
idempotence. Planting either one as a true statement (`= 3`, `= Fin 4`) turns the build
red with "Failing block did not fail", so each block rejects for the stated
reason.

==== AffineScript (18 tests)

Properties taken from the borrow checker's own contract —
`affinescript/lib/borrow.ml`, module docstring — not invented here:

[cols="2,1,4"]
!===
! Module ! Tests ! Guarantee

! `AffineScript/Affinity`
! 9
! *No use after move.* Affine = at most once: dropping is fine, two uses is not. Includes `affineIsWeakerThanLinear`, because conflating affine with linear would silently reject valid programs.

! `AffineScript/Borrow`
! 9
! *No conflicting borrows* (Shared XOR Exclusive over overlapping lifetimes) and *borrows don't outlive owners* (containment at both ends).
!===

**These are properties of a model, not a proof about the OCaml.** Passing them
says nothing about whether `lib/borrow.ml` is correct. They pin down what the
guarantees mean precisely enough to disagree with — the honest limit of this
tier, and both modules say so at the top.

**Half the assertions are rejections on purpose.** A suite that only checks
happy paths passes just as well against a checker that accepts everything.
Verified by making that mistake deliberately — replacing
`affine v t = useCount v t <= 1` with `affine v t = True` gives
**61/63, SUITE: FAIL, exit 1**. The suite detects a vacuous checker.

==== Two deliberate honesty choices in these suites

`Transfer` includes `intStringTransfer : Transfer Int String`, which is a
section/retraction and **not** an isomorphism — `"007"` and `"7"` both parse to
`7`. The suite asserts only the direction that holds. A test asserting the
reverse round trip would be false, and a false test is worse than a missing one.

`Traversal.traverseMaybeShortCircuits` returns `True` on `[]` because
`traverse` on the empty list is `Just []`, so there is nothing to short-circuit.
That vacuity is stated in the source rather than hidden behind a passing tick.

=== `proven-ordering-laws` — laws of proven's own code (8 theorems)

Added 2026-10-07. Every other proof in this document is about code this
repository defines. These eight are about code another estate repository ships:
`mergeVT`, `zeroVT` and `tickVT` from `Proven.SafeOrdering` in
https://github.com/hyperpolymath/proven[hyperpolymath/proven], *imported, not
copied*, at the commit pinned in `integrations/proven/PROVEN_PIN`
(`53600326ca31f6f99767c5371cc77af2dade996c`).

[cols="2,5"]
|===
| Theorem | Statement (all `n`, all clocks)

| `mergeVTComm` | `mergeVT a b = mergeVT b a`
| `mergeVTAssoc` | `mergeVT a (mergeVT b c) = mergeVT (mergeVT a b) c`
| `mergeVTIdem` | `mergeVT a a = a`
| `mergeVTZeroL` / `mergeVTZeroR` | `zeroVT` is a two-sided identity of `mergeVT`
| `mergeVTUpperL` / `mergeVTUpperR` | each entry of either input is `LTE` the same entry of the merge
| `tickVTAdvances` | `tickVT i` raises entry `i` by exactly one
|===

Together these make `mergeVT` a join-semilattice with `zeroVT` as bottom. That
is what lets a vector clock be merged in any message order, any grouping, and
with redelivery, without changing the result. Proofs are in
`integrations/proven/src/ProvenSubject/OrderingLaws.idr`. The rung-built tests
and three reject controls are in `OrderingLawsTests.idr`: merge is not a sum,
tick is not idempotent, and a rung citing `mergeVTIdem` for commutativity does
not elaborate.

*How it is run.* `scripts/prove-proven-ordering.sh <proven checkout>` extracts
proven's `src/` at the pin with `git archive` and installs `Proven.SafeOrdering`
into a throwaway package prefix. It then builds and runs the
`proven-ordering-laws` executable. CI fetches the pinned commit and runs this
as a hard gate. Unlike subject grading, it is not `continue-on-error`: the pin
makes it this repository's invariant.

*Verified 2026-10-07.* At the pin: **8/8 Actually-Proven, exit 0**. With
proven's `mergeVT` mutated from pointwise `max` to pointwise `+` and pinned:
**exit 1**, with five laws rejected at compile time (`mergeVTComm`,
`mergeVTAssoc`, `mergeVTIdem`, `mergeVTZeroL`, `mergeVTUpperL`). The rest fail
with them because they are built from those five. A malformed pin, or a pin
missing from the checkout, exits 2.

*What this does not cover.* These eight tests are a separate executable. They
are not counted in the spec suite's 29 Actually-Proven properties above. They
prove laws of proven at one commit, not of proven's `main`. A pin bump is
the moment they are re-checked.

== Not implemented, on purpose

`EchoTypes/Safety.idr` and `EchoTypes/Invariance.idr` are named in the spec and
are **not** written. There is no formal definition of an echo type to encode:
the spec names the phrase without defining it. (CORRECTED 2026-08-10: upstream
`echo-types` now carries ~205 `--safe` Agda modules — the earlier "0 proof
files" reading is stale. It still contains no *Idris2* artefacts, so encoding
its semantics here remains a port, not a citation; see
`src/ProvenTests/EchoTypes/README.adoc` for the current statement.)

Full reasoning and the three things that would unblock it:
`src/ProvenTests/EchoTypes/README.adoc`.

== How to verify these claims

[source,console]
----
$ idris2 --typecheck proven-tests.ipkg        # 32 modules
$ idris2 --install   proven-tests.ipkg
$ idris2 --build     proven-tests-suite.ipkg && ./build/exec/proven-tests-suite
$ idris2 --build     proven-spec-suite.ipkg  && ./build/exec/proven-spec-suite
----

Use `idris2 --typecheck <ipkg>`. Do **not** use per-file `idris2 --check` as a
gate: it prints `Error:` and still exits `0`, so a CI step built on it passes
while the code is broken. Confirmed again on Idris2 0.7.0 while writing these
modules.
